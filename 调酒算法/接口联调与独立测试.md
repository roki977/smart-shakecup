# 接口联调与独立测试

## 已实现与已验证

新增bridge.py：设备包转算法输入、算法结果转网站Frame/SessionResult。新增server.py：本地HTTP服务，绑定127.0.0.1，与网站静态资源同源。

启动：`python3 server.py --port 8766`，默认从同级调酒网站/dist提供页面。不改变原8765预览。此服务用于联调，内存会话、单进程，不是持久化生产部署。

HTTP：
- POST /api/sessions：`{algorithm:规则配置,reference:阶段参考,source:"measured|simulated|replay",start_t:0,feature_config:可选,device:可选}` → `{id}`。
- POST /api/sessions/{id}/data：`{frames:[特征帧]}` 或 `{packet:MQTT原始包}` → 网站Frame。
- GET /api/sessions/{id}/snapshot → 网站Frame；接收停滞超过1.5秒标lost并隐藏当前值。
- POST /api/sessions/{id}/event：`{action:"transition",t:秒,evidence:"confirmed|validated_event"}`；也支持pause/resume/cancel。
- POST /api/sessions/{id}/finish：`{intent:"complete|partial"}` → 网站SessionResult，重复结束返回相同结果。complete条件不足返回400，保留会话可重试或partial。

实际验证了HTTP完整请求链，并用网站当前dist/adapters.js导出的validateFrame和validateResult验证Python返回值。共27项Python测试通过。

## 网站还有两个真实接线点

1. 页面当前SessionConfig不含完整算法规则和实测参考。网站适配器要用选择的ID/版本加载适用规则与参考，组装创建请求；不能直接把旧表单原样发来，也不能为了启动而暗塞模拟参考。
2. DeviceAdapter收到的MQTT包须转发到/data。server.py不自带MQTT订阅客户端，网页转发与后端独立订阅二选一，不能两路重复送。

页面已经有BackendAdapter的创建、快照和结束路径，但这两点尚未完成完整浏览器联调。单独启动server.py不会自动把页面切换成真实算法模式。网站窗口负责剩余适配并验证页面操作。

## 硬件必须确认的协议项

`device={epoch_ms:本轮设备时间原点,acc_unit:"g或m/s2",packet_time:"first或last",probe:液温探头索引}`。

- ms是设备毫秒，统一相对秒；acc_hz使用包声明的真实采样率，原始acc为有符号三轴数组。
- g乘9.80665转m/s²。旧hz和amp厘米字段不进入正式评分。
- packet_time明确ms对应一包acc第一点还是最后一点。现有说明未确定，禁止默猜；epoch_ms必须不晚于首个有效样本。
- 多探头指定液温索引，不对探头取中位数。
- 15Hz测温若以10Hz打包发送，每包一个temp会丢掉一部分样本。可发送temperature_samples:[{ms,value}]保留各自采样时间。只有temp时按包ms记录，不能宣称保留了15Hz原始测温。
- 重复温度时间不新增观测；IMU重复/乱序/时间回退拒绝并报告，设备重启须重建时间原点和会话，不把网络到达时间替代采样时间。
- 当前只做软件协议测试，尚无实物包验证、真实设备时钟与传感器标定结果。

## 独立测试窗口应该先拿什么

第一轮先给“算法与网站对接.md”、本文件、输入JSON结构与数学公式，不给engine.py或我们的结果文件，不让它调用本程序生成期望。

它独立写：输入、预期结果、计算依据、可接受的数值误差、为什么能抓出错误。先固定案例及预期，再运行本程序。案例无法精确预言频谱输出时，检验区间/不变量，不随意写一个精确小数。

需要覆盖：
1. 手算AHP/容差/损失/分数；不同采样间隔但同一持续偏差。
2. 同频同幅换相位/固定坐标方向/100与200Hz；改变频率或幅度；强谐波、起停、非周期。
3. 当前分数恢复但最终保留损失；追加正确时间不能洗掉损失；短前缀不能完整满分。
4. 异常持续、迟滞恢复、边界抖动、正负交替、Top-K不凑数、缺测不当正常。
5. 原始包g与m/s²、ms与s、批量采样时间锚点、多探头、丢包、重复包、重启。
6. HTTP创建/送数据/快照/结束，前端展示和冻结结果对应。

第二轮再开放源码做白盒审查，查找独立案例未想到的逻辑分支。第三轮用硬件录制包和调酒师标记验证实测效果。任何一轮都不需要让AI在线参与评分。

同一份合成信号与自己比较得100，只能证明贯通一致；不能单独证明识别能力、阈值合理或口感准确。真实算法有效性要靠独立预期与实测，两者缺一不能夸大。
