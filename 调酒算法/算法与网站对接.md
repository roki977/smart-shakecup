# 调酒算法与网站对接

本轮把第4、5、6项落为可执行Python模块；不调用AI。入口 `engine.py`，批量回放入口 `run.py`，依赖 NumPy。现有测试环境 NumPy 2.5.2。

## 一、统一设计

```text
准备层
  选择配方版本 + 原料/用量/冰/杯体 + 对应专业参考 + 规则版本
       ↓
原理层
  温度15Hz ───────────────────────────→ T
  IMU100/200Hz → 三轴预处理 → 周期f + 合成加速度RMS幅度A
       ↓
  确认当前阶段 → 与同阶段参考按实际时间比较（不伸缩时间）
       ↓
  分项时间加权MSE → RMSE → 容差外偏差q → 层次AHP → 窗口损失
       ├─ 当前符合度，可回升
       ├─ 固定参考时长累积损失 → 确认完成后的最终成绩
       └─ 持续超限/迟滞 → 异常时间段 → 按贡献排序，最多K条
       ↓
原理到Web
  当前状态、T/f/A、有效性、偏差方向、分数、异常事件
       + 知识库的操作/位置/前置状态/来源
       ↓
Web层
  图鉴 → 准备 → 制作自动提示 → 完成 → 冻结结果 → 复盘/分享
```

本窗口负责确定性计算；网站窗口负责2、7、8、9。10暂不开展。知识库文本不生成数值参考，调酒师实测才是数值参考；图鉴里暂无实测的配方不能显示真实跟练评分。

A是m/s²的RMS加速度，不是手部位移或液体流速；没有混合程度/稀释率/压力算法。原始a-t保留回放，不逐点计入主分数。

## 二、代码已经实现什么

| 模块/入口 | 实现 |
|---|---|
| `features(imu, temperature, feature_config)` | 三轴因果一阶高通、小间隔均匀重采样、窗口去均值、三轴合计频谱与归一化自相关、周期一致性检查、RMS；低运动/非周期/缺测/起步分开 |
| `Engine.start / push` | 进入阶段、消费特征帧，输出当前比较结果与已确认的活动异常 |
| `transition(t, evidence)` | 显式确认或经验证事件推动阶段切换；清理阶段窗口与事件 |
| `pause / resume / cancel / finish` | 暂停不抹除实际流逝时间；取消无最终成绩；结束冻结记录 |
| `ahp / score` | 两层AHP和指数分数映射 |
| `calibrate_tolerance` | 对独立认可记录的窗口RMSE沿记录维取分位数，再取测量下限；不以当前用户残差更新阈值 |
| `run.py` | JSON输入→特征/评分/异常→JSON输出，可直接用外部测试案例校验 |

实时系统可把设备数据追加到缓冲区，调用features后仅把新时间戳帧传给Engine；当前features提供确定性回放/累计缓冲接口，尚未做长时间流式性能优化，也未接具体ESP32传输协议。网站通过适配层接入，避免重写第二套正式评分。

## 三、公式与实现口径

- `wT=r1/(1+r1)`；`wf=r2/((1+r1)(1+r2))`；`wA=1/((1+r1)(1+r2))`。
- `RMSE_j=sqrt(sum(residual²×dt)/sum(valid_dt))`。误差窗口按秒截取，保留带符号残差。
- `q_j=max(RMSE_j-b_j,0)/s_j`。
- `loss_now=sum(w_j*q_j²)`，不是把MSE再平方。
- `loss_total += beta_stage*loss_now*dt/reference_evaluation_duration`。
- `score_now=100*(anchor_score/100)^(loss_now/anchor_loss)`。
- `score_final=100*(anchor_score/100)^(loss_total/anchor_loss)`，只有完成要求及数据覆盖满足才给出。

`evaluate_from_s`显式定义可评价起点，排除特征识别启动窗口；固定分母为`end_s-evaluate_from_s`。不是用户制作越久分母越大。阶段的绝对时间戳保留；参考时间从当前阶段开始计算。

帧值以当前帧代表上一帧至当前帧的区间（右端矩形积分），最后一段不足一个采样步长时应提供结束时刻帧。参考只在有效点之间按阶段时间线性插值，不外推。温度特征在输出时刻使用最近有效测温值，并检查陈旧时间，不取未来测温数据。

容差可以是阶段常数，也可以是 `{t,value,valid}` 点列；本轮开始前固定。未进入某阶段评分的通道由阶段配置声明，不把临时缺失的通道删除后重新归一化权重。

一个窗口内正负残差都占超过20%有效时间时当前实现标`mixed`，否则标high/low/equal。这是方向展示规则，不是正式口感阈值；后续可随案例调整版本。

## 四、阶段与异常

准备好后start；阶段转移接收 `confirmed` 或 `validated_event`。算法当前不自动推断“加冰/加料/过滤”。网站不能仅因播放时间到了就伪造validated_event。已有可靠识别器可以提供事件；尚不能识别的操作使用明确确认。

暂停后参考时钟继续流逝，不通过移动时间轴抹除停顿。暂停区间不评行为、算覆盖缺失；持续输入有效低运动则f=0、A低，可正常评估要求摇和阶段的停顿。

异常规则：RMSE/b>1持续on_s确认；低于recovery_ratio持续off_s关闭；缺测中断行为判断且不能当成恢复。相邻同阶段同变量事件只有在已观察到恢复的短间隔内合并。按与评分相同的超限贡献排序，Top-K只是上限，不强凑。

返回high/low只表示温度高低、频率快慢、加速度幅度大小；不会把这些自动写成“手臂摇幅不足”等未验证原因。7项解释由网站对接知识库和后续规则，事实与原因分开。

## 五、输入输出契约

### 原始数据

- `imu`: `[{t, ax, ay, az, valid?}]`，秒、m/s²；时间有序。设备已经标记的饱和/无效点用valid=false；未提供设备量程时算法不会声称能自动识别饱和。
- `temperature`: `[{t, value, valid?}]`，秒、°C。
- 两路必须处于同一时钟坐标；硬件偏移校准尚不能由算法凭空推断。

### 特征帧

`{t,T,f,A,motion,feature_version,window,quality}`。无效值是null。f=0仅在低运动条件下表示无往返周期；非周期运动的f为null、A仍可有效。

也可直接提供特征帧跳过原始数据处理，便于网站独立测试评分。每帧至少带t/T/f/A/feature_version。

### 配置

参照 `测试输入.json` 的config：版本、配方版本、特征版本、r1/r2、分数锚点、误差窗口、允许间隔、覆盖要求、事件持续/恢复/合并/K，以及stages。

每个stage指定id、可评价起止秒、beta、channels、tolerance和scale。所有这些参数在开做前锁定。测试配置明确为`synthetic_not_calibrated`；没有默认的正式专业参数。

### 参考

`{id,recipe_version,feature_version,stages:{stage_id:{T:[points],f:[points],A:[points]}}}`。

知识库参考记录保存整轮曲线；进入引擎前，参考管理/适配层按已确认阶段切出这里的stage-relative曲线，并选择适用规则。此切分不能只靠酒名猜测。本轮没有把未标注的整轮参考自动切成语义阶段。

### 运行结果

`run.py`返回 `features / timeline / result`。timeline包含每帧三项value/reference/residual/mse/rmse/tolerance/q/direction、当前分数、累积损失、活动异常。result包含complete、final_score、loss、阶段覆盖、全部事件、截取后的反馈事件、版本及问题列表。

缺必需数据或提前结束时final_score=null，不转换为0分或100分。已知通道的损失仍保留，不把缺失数据变成满分捷径。finish后的push不再接受数据。

## 六、现在怎样运行

在本目录中：

```bash
python3 -m pip install -r requirements.txt
python3 -m unittest -v
python3 run.py 测试输入.json --output 测试结果.json
python3 run.py 原始数据测试输入.json --output 原始数据测试结果.json
```

第一份是既定算例，最终应约74.265421；第二份贯通原始信号→特征→评分，同一合成信号应为100。这是代码一致性验证，不是实测调酒验证。

## 七、交给网站窗口的独立测试安排

用户将单独安排网站窗口产生测试案例。本轮先交付契约与设计，勿提前把本模块输出当作测试标准。

后续案例可以直接交一份run.py接受的JSON，另附预期：正常完成/提前结束/缺测，分项偏差方向，是否产生事件，当前分数是否恢复，最终损失是否保留。有明确算式的案例提供独立算出的目标数值；真实信号不应事先承诺精确味觉评分。

优先覆盖相位变化、频率/幅度分别变化、100/200Hz、停顿/非周期、正负交替、温度与IMU不同采样率、阶段切换、无参考时段及完成冻结。用户后续给的案例将作为独立验收，不替换现有单元测试。

## 八、当前结论

算法链不需要AI：信号处理、阶段状态、误差、权重、阈值和排序都应确定、可回放。AI可用于离线整理知识资料，但不放在评分和实时判错的必要链路里。

已实现的是可执行计算结构；真实硬件/专家数据的参数标定、设备对时、实际周期识别准确率仍需案例和实测。规则不明的地方没有用AI猜测补齐。
