# 网站与知识库接入

本轮分工：网站窗口负责第2、7、8、9项；本窗口负责知识库、参考数据契约与后续计算。第10项不开展。本轮不新增第11项任务。

## 可直接接入的文件

`网站图鉴接口.json` 是可导入的静态数据契约，不是已经部署的HTTP服务。它包括117个配方来源版本、来源、元件和实测参考记录。`构建.py` 可重新导出。网站接入层应隔离数据加载，之后可替换为API。

每款配方现在有 `recipe_version`（内容哈希）和 `reference_binding`：

- `awaiting_measurement`：只有来源流程，尚无实测参考。可看图鉴/教学，不可显示虚构标准曲线或真实评分。
- `pending_review`：已有记录，尚未有审核合格的参考。
- `approved_available`：存在同版本的审核通过参考；仍需检查制作条件及通道有效性，不等于适合所有用户配置。
- `reference_ids`：关联记录。配方变更后哈希改变，旧曲线保留但不会自动为新版背书。

知识库现有102款IBA全目录和15个补充来源版本；不能宣称覆盖世界所有酒或所有做法。

## 标准曲线预留与存取

`标准曲线记录.json` 初始 records 为空，不能用模拟数据填成专业参考。

`标准曲线.py` 提供 `ReferenceStore.list(recipe_id, approved_only)`、`save(record)`；目前是单写入进程的本地文件存储，网站多用户持久化需由网站后端承接，不能把它称为线上数据库。保存不允许覆盖ID，重建知识库不删除记录。当前没有网页上传功能或审核状态更新API。

记录字段：

| 字段 | 含义 |
|---|---|
| id / session_id | 唯一参考记录 / 对应制作记录 |
| recipe_id / recipe_version | 配方来源版本及内容哈希，必须匹配 |
| bartender_id / captured_at | 采集者与采集时间，时间使用ISO8601带时区 |
| origin | measured；演示数据应使用独立数据入口 |
| status / review | pending_review、approved、rejected；approved需reviewer_id、reviewed_at、basis |
| conditions | 本次原料与用量、冰类型/用量、杯体材质/容量、准备条件；网站保留完整原始值 |
| feature_version | f/A计算算法版本，不能仅凭字段同名就认定可比较 |
| curves | T、f、A三个键。未获得通道为null，不得补0 |

每个非空通道：`{"unit":"degC或Hz或m/s2","time_unit":"s","points":[{"t":相对秒数,"value":数值或null,"valid":true或false}]}`。

T为温度；f为频率；A为有效加速度RMS，不能写成液体速度或位移幅度。时间戳各通道分别保存，无须强行相同点数；温度15Hz，IMU原始100/200Hz尚需实际核实，特征输出频率不能冒充原始频率。

无效点value为null；有效点为有限数值；t非负、递增。缺一个通道时可以保存部分实测记录，但前端必须显示缺失，不得按完整三通道打分。

审核与conditions当前仅作基本结构校验，不能自动证明真人采集、数据质量或配方条件相容。后续参考管理负责业务审核。

## 第2项：原料和酒款图鉴

检查两类图鉴是否分开；酒款引用知识库配方ID及版本，显示步骤、来源、分支和参考状态。普通来源配方不能标成“调酒师实测标准”。

原料图鉴保留名称、规格、用量和感官标签来源；未经证实的标签不要自动生成。IBA原料仍含原文行，补充来源含品牌名称，尚未统一为产品原料ID。网站需建立映射并保留原值，不把同类品牌自动视作等价替代。

支持创建/修改配方及新版本；个人配方不能冒用IBA来源或继承他人曲线。经典来源版本保持只读。

## 第7项：解释与建议

检查事实、候选原因、建议、证据不足是否分层展示；异常应带时段、变量、方向、来源证据。当前知识库没有成熟诊断规则，不能宣称所有异常都能精确定位原因。

来源路径中先后关系并非全部是硬约束。不能把所有顺序差异都扣分。杯体静止不代表没用吧勺；温降不能唯一确认加冰。缺算法时留解释接口和明确未接入状态，模拟例子标模拟。

## 第8项：完整制作与复盘

检查选配方→准备→连接→开始→自动阶段指导→确认完成→冻结记录与分数→结果→复盘→保存/历史。

制作中不要求频繁点电脑；完成确认需清楚，停止后历史曲线不可继续变化。处理断连、过期数据、缺通道、取消、提前结束、无参考版本。当前符合度与最终分数分开，不能无论怎样操作都接近满分。

## 第9项：社区与参考审核

检查作品、配方、曲线分享及跟练入口，引用不可变配方版本与记录ID。

至少三次独立、条件一致且曲线接近是候选门槛；重复上传同一记录不计三次。这个门槛不等于专业质量认证。阈值未标定时标待审核，不假装审核通过。

分享、审核和专业参考是不同状态；无真实后端时明确浏览器本地演示，不能宣称已有跨用户社区。授权范围、删除/撤回和无权限状态要有入口/占位。
